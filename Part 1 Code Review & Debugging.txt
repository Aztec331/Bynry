1. No transaction safety (double commit), Product and Inventory are saved using two separate database commits.

Create Product

WRONG:

RIGHT:

price ≥ 0

Never trust client input — always validate before saving.

1. Price precision issue (float vs decimal),The API stores price using floating-point numbers, which causes rounding errors for money values.

0.1 + 0.2
= 0.30000000000000004 ❌

0.1 + 0.2
= 0.3 ✅

### ✅ Solution

- **API:** Accept price as a number (JSON)
- **Backend:** Convert price to `Decimal`
- **Database:** Store price as `DECIMAL(10,2)`

JSON price → Decimal("99.99") → DECIMAL(10,2)

Always store money using decimal, never float.

1. No error handling in the API,The API assumes everything will work and does not handle database or logic errors.

### ✅ Solution

- Wrap database operations in `try / except`
- Handle:
    - duplicate SKU
    - invalid data

- Return clear error messages

APIs must fail gracefully, not crash.
